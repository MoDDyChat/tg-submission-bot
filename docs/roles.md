## Как назначаются роли

### MODERATOR
Задаётся через переменную окружения `MODERATOR_IDS` (через запятую):
```env
MODERATOR_IDS=123456789,987654321
```
При каждом обращении пользователя middleware `AuthMiddleware` выполняет upsert и синхронизирует флаг `is_moderator` в таблице `users` на основе `config.moderator_ids`. Изменение `MODERATOR_IDS` вступает в силу после перезапуска бота.

### ADMIN
Задаётся через переменную окружения `ADMIN_IDS` (через запятую). Должен быть подмножеством `MODERATOR_IDS`:
```env
ADMIN_IDS=123456789
```
При старте бота `sync_admin_flags()` (в `core/bot.py`) устанавливает/снимает `is_admin=True` в таблице `users` для всех записей:
- Пользователи из `ADMIN_IDS` → `is_admin=True`
- Все остальные (включая удалённых из `ADMIN_IDS`) → `is_admin=False`
- При пустом `ADMIN_IDS` — все флаги `is_admin` сбрасываются в `False`

Если `ADMIN_IDS` не задан — ни один пользователь не имеет прав администратора. Роль Admin в runtime определяется полем `users.is_admin`, а не только конфигом.

## Фильтры в коде

| Фильтр | Файл | Логика |
|--------|------|--------|
| `IsModerator` | `filters/is_moderator.py` | `event.from_user.id in config.moderator_ids` |
| `IsAdmin` | `filters/is_admin.py` | `db_user.is_admin == True` |

Роутер модератора (`handlers/moderator/__init__.py`) использует `IsModerator` на уровне роутера — все его handler-ы автоматически видят только модераторов. `IsAdmin` применяется точечно внутри handler-ов (например, кнопка Recover).
