# tg-submission-bot — бот-предложка для Telegram-канала

[English](README.md) · **Русский**

Telegram-бот для приёма творческого контента (арты, анимации, видео) от зрителей,
модерации в отдельной форум-группе и отложенной публикации в канал.

---

## Что умеет

**Зритель** (любой пользователь):
- `/start` — получает правила предложки (текст настраивается, см. `RULES_PATH`)
- отправляет фото / видео / GIF / документ / текст, в том числе альбомами
- видит подтверждение «Пост #N принят» и может отменить своё предложение
- получает уведомление, когда пост опубликован или отклонён

**Модератор** (роль хранится в базе; `MODERATOR_IDS` только выдаёт её при старте):
- каждый зритель получает **свою тему** в приватной форум-группе; там появляются медиа и карточка поста со статусом
- превью поста, редактирование описания, добавление/удаление медиа
- система тегов через визард с пресетами (разделы + элементы, редактируются прямо в боте)
- публикация сразу или по расписанию, снятие с расписания, доска очереди в General-топике
- отклонение поста (с причиной или тихо), бан автора, личный контакт с автором

**Администратор** (`ADMIN_IDS` выдаёт роль так же, при старте):
- всё то же, что и модератор: админ — это модератор с дополнительными правами,
  дублировать его ID в `MODERATOR_IDS` не нужно
- раздел «Модераторы» — назначение и снятие модераторов прямо в боте, без правки `.env`
  и без перезапуска (см. [Управление модераторами](#управление-модераторами))
- кнопка «Recover постов» — восстановление потерянных карточек в темах
- DM-уведомления о правках пресетов, банах и каждой смене ролей

Коротко: модераторы разбирают и публикуют предложку, админы вдобавок управляют составом
модераторов, получают инструмент восстановления и уведомления о правках пресетов и банах.
Если вы ведёте бота в одиночку — укажите свой ID в `ADMIN_IDS`, а `MODERATOR_IDS` оставьте пустым.

Подробности: [`docs/pipelines.md`](docs/pipelines.md), [`docs/roles.md`](docs/roles.md),
[`docs/publishing.md`](docs/publishing.md), [`docs/tags-system.md`](docs/tags-system.md).

## Требования

- Сервер с Docker и Docker Compose — PostgreSQL и Redis уже входят в `docker-compose.yml`
- Аккаунт Telegram и права создать канал и группу

Порядок такой: [Шаг 1](#шаг-1-подготовка-в-telegram) — подготовить бота, канал и группу

[Шаг 3](#шаг-3-запуск) — запустить. Занимает 15–20 минут.

## Шаг 1. Подготовка в Telegram

Всё это делается один раз, руками, до первого запуска.

### 1.1. Создать бота

1. Написать [@BotFather](https://t.me/BotFather) → `/newbot` → задать имя и username.
2. Сохранить токен вида `1234567890:AAH...` — это `BOT__TOKEN`.
3. Там же: `/mybots` → ваш бот → **Bot Settings → Group Privacy → Turn off**.
   Без этого бот не увидит часть событий в группе модерации.

### 1.2. Создать канал для публикаций

1. Создать канал (публичный или приватный) — туда бот будет постить.
2. Добавить бота **администратором** с правом «Публикация сообщений».

### 1.3. Создать группу модерации

1. Создать **приватную супергруппу**.
2. В настройках группы включить **Темы (Topics / Forum)** — это обязательно,
   бот заводит по теме на каждого зрителя.
3. Добавить бота администратором с правами: «Управление темами», «Отправка сообщений»,
   «Редактирование сообщений», «Удаление сообщений», «Закрепление сообщений».
4. Добавить в группу всех модераторов.

### 1.4. Узнать ID канала и группы

ID выглядят как `-1001234567890` (всегда со знаком минус и префиксом `-100`).

Самый простой способ: переслать любое сообщение из канала/группы боту
[@userinfobot](https://t.me/userinfobot) или [@getidsbot](https://t.me/getidsbot) —
он покажет `Forwarded from chat: -100...`.

Свой личный ID (для `MODERATOR_IDS`) тот же бот покажет, если просто написать ему `/start`.

> Модераторы должны хотя бы раз написать боту в личку `/start` — иначе бот не сможет
> отправлять им уведомления.

## Шаг 2. Установка

```bash
git clone https://github.com/<your-account>/tg-submission-bot.git
cd tg-submission-bot
cp .env.example .env
```

Открыть `.env` и заполнить (полный список переменных — ниже):

```env
BOT__TOKEN=1234567890:AAH...

# Пароль придумайте любой — с ним поднимется контейнер PostgreSQL из compose.
DB__HOST=postgres
DB__PORT=5432
DB__NAME=tg_submission_bot
DB__USER=postgres
DB__PASSWORD=<свой пароль>

# Это списки для первичной выдачи ролей, а не весь состав: перечисленные ID
# получают роль при старте, дальше состав правится прямо в боте.
# Несколько ID — через запятую в одной строке:
#   MODERATOR_IDS=123456789,987654321,555444333
MODERATOR_IDS=123456789
# Админы получают права модератора автоматически — выше их повторять не нужно
ADMIN_IDS=987654321

CHANNEL_ID=-1001111111111
MODERATOR_GROUP_ID=-1002222222222

TIMEZONE=Europe/Moscow
REDIS_URL=redis://redis:6379/0
RULES_PATH=config/rules.txt
```

### Текст правил

`/start` для зрителя показывает содержимое файла из `RULES_PATH` (HTML-разметка Telegram:
`<b>`, `<i>`, `<a href="...">`). Скопируйте пример и отредактируйте под свой канал:

```bash
cp config/rules.example.txt config/rules.txt
```

Если файла нет — используется встроенный текст из `src/core/messages.py`.

### Остальные тексты бота

Все остальные пользовательские строки (кнопки, промпты, уведомления) живут в `config/messages.yaml`
(путь задаётся через `MESSAGES_PATH`). Можно редактировать любое значение — файл проверяется при
старте: если правка убирает или переименовывает нужный `{плейсхолдер}`, бот не запустится и покажет
понятную ошибку вместо падения посреди диалога. Ключи, которых нет в файле, берутся из встроенных
значений в `src/core/messages.py`.

## Шаг 3. Запуск

```bash
docker compose up -d --build
```

Одна команда поднимает три контейнера: бот, PostgreSQL и Redis. Таблицы в базе
бот создаёт сам при первом старте — никаких команд для этого выполнять не нужно.

Убедиться, что всё поднялось:

```bash
docker compose logs -f bot
```

В логах при успешном старте видно: соединение с БД → `get_me()` → регистрация команд →
проверка доступа к каналу и группе → создание навигационного сообщения в General-топике →
запуск планировщика → старт polling.

Если бот не имеет доступа к каналу или группе — он скажет об этом явно и не запустится.

Всё, бот работает. Дальше — напишите ему `/start` из аккаунта модератора.

## Управление модераторами

**Источник правды по ролям — база данных.** `MODERATOR_IDS` / `ADMIN_IDS` нужны только для
первичной выдачи ролей и как аварийный доступ: при каждом старте бот выдаёт перечисленным ID
их роль (заводя запись пользователя, даже если человек ни разу не писал боту) и **никогда не
отбирает роль**. Убрать ID из списка и перезапустить бота — не значит снять права.

Всё остальное делается прямо в боте: `/start` → **Управление → Модераторы** (раздел виден
только администраторам). Оттуда доступно:

- **Создать ссылку-приглашение** — одноразовая ссылка вида
  `https://t.me/<бот>?start=modinvite_<токен>`, живёт 24 часа. Модератором станет тот, кто
  откроет её первым; после использования ссылка сгорает, так что переслать её повторно
  бесполезно. Просроченные ссылки чистятся ежедневной задачей.
- **Добавить по Telegram ID** — ввести ID напрямую, без промежуточной ссылки.
- **Снять модератора** — снимает обе роли, гасит его неиспользованные приглашения и
  принудительно снимает блокировки редактирования постов, которые он держал, — ничего
  не зависает.
- **Выдать / забрать админа** — при снятии админских прав человек остаётся модератором.

Ограничения (проверяются в той же транзакции, что и сама запись):

- нельзя менять свою собственную роль;
- нельзя снять последнего администратора;
- забаненному нельзя выдать роль, а обладателю роли — нельзя выдать бан: сначала снимите роль;
- пользователь из `MODERATOR_IDS` / `ADMIN_IDS` **защищён конфигом** — снять его через
  интерфейс нельзя (при следующем перезапуске роль вернётся). Чтобы убрать такого человека,
  сначала уберите его ID из `.env`.

О каждой смене ролей уходит DM всем админам (строка аудита), а самому пользователю —
отдельное уведомление.

Подробности: [`docs/roles.md`](docs/roles.md).

## Запуск без Docker

Понадобятся свои PostgreSQL 14+ и (по желанию) Redis.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

# в .env: DB__HOST=localhost, REDIS_URL=redis://localhost:6379/0
python main.py
```

## Переменные окружения

| Переменная | Обязательна | По умолчанию | Описание |
|---|---|---|---|
| `BOT__TOKEN` | да | — | Токен от @BotFather |
| `DB__HOST` | да | `postgres` | Хост PostgreSQL |
| `DB__PORT` | нет | `5432` | Порт PostgreSQL |
| `DB__NAME` | нет | `tg_submission_bot` | Имя базы |
| `DB__USER` | нет | `postgres` | Пользователь БД |
| `DB__PASSWORD` | да | — | Пароль БД |
| `MODERATOR_IDS` | да* | — | Стартовые ID модераторов через запятую: `123456789,987654321` |
| `ADMIN_IDS` | нет | пусто | Стартовые ID админов; права модератора получают автоматически |
| `CHANNEL_ID` | да | — | ID канала публикации (`-100...`) |
| `MODERATOR_GROUP_ID` | да | — | ID форум-группы модерации (`-100...`) |
| `TIMEZONE` | нет | `Europe/Moscow` | Таймзона для расписания публикаций |
| `LOG_LEVEL` | нет | `INFO` | `DEBUG` / `INFO` / `WARNING` / `ERROR` |
| `RULES_PATH` | нет | `config/rules.txt` | Файл с текстом правил (HTML) |
| `REDIS_URL` | нет | пусто | Есть → persistent FSM; нет → состояния в памяти |
| `EDIT_LOCK_TTL_SECONDS` | нет | `300` | TTL блокировки редактирования поста |
| `PROXY_URL` | нет | пусто | SOCKS5/HTTP-прокси к Telegram API |
| `SILENT_MODERATOR_NOTIFICATIONS` | нет | `true` | Модгруппа и DM админам — без пуш-пинга |
| `API_HOST` / `API_PORT` | нет | `0.0.0.0` / `5400` | HTTP-сервер health/metrics |
| `LOG_DIR` | нет | `/logs` в образе | Каталог лог-файла; вне Docker — `<проект>/logs` |

\* Заполнить нужно хотя бы один из списков `MODERATOR_IDS` / `ADMIN_IDS` — любой из них по отдельности подойдёт.
Оба списка — **стартовые**, а не живой состав модераторов, см. [Управление модераторами](#управление-модераторами).

Двойное подчёркивание в `BOT__TOKEN` и `DB__*` — не опечатка: так pydantic-settings
раскладывает переменные по вложенным секциям конфига.

## Эксплуатация

**Обновление до новой версии:**

```bash
git pull
docker compose up -d --build
```

Схема БД обновится сама при старте контейнера.

**Свои настройки инфраструктуры** (пути логов, внешние сети, готовый сервер PostgreSQL
вместо контейнера, второй инстанс бота) кладите в `docker-compose.override.yml` —
Compose подхватывает его автоматически, и файл не попадает в git.

**Логи:** пишутся в `/logs` внутри контейнера (смонтируйте свой volume в `docker-compose.yml`)
и в stdout — `docker compose logs`.

**Health и метрики:**

- `GET http://<host>:5400/api/v1/health` — JSON для healthcheck. `503` = недоступен
  Telegram API или PostgreSQL; `degraded` = упал Redis или планировщик
- `GET http://<host>:5400/api/v1/metrics` — Prometheus-формат (`tgarts_*`)

**Бэкап:** данные — только в PostgreSQL. Медиафайлы не скачиваются, хранится лишь
Telegram `file_id`, поэтому достаточно `pg_dump`.

> ⚠️ `file_id` действителен только для **того бота**, который его получил. При смене
> токена бота старые посты перестанут публиковаться.

## Настройка под свой канал

| Что | Где |
|---|---|
| Текст правил для зрителей (`/start`) | файл из `RULES_PATH`, например `config/rules.txt` |
| Названия и иконки статусов тем | `config/topic_statuses.json` |
| Пресеты тегов | прямо в боте: `/start` → «Управление» → «Пресеты тегов» |
| Остальные тексты бота | `config/messages.yaml`, путь задаётся через `MESSAGES_PATH` |

## Частые проблемы

| Симптом | Причина |
|---|---|
| `Telegram ID не может быть равен 0` при старте | не заполнен `CHANNEL_ID` / `MODERATOR_GROUP_ID` |
| `channel_id и moderator_group_id должны быть отрицательными` | указан ID без префикса `-100` |
| `Нужен хотя бы один ID в MODERATOR_IDS или ADMIN_IDS` | оба списка пусты |
| Бот не создаёт темы | в группе не включены Topics или у бота нет права «Управление темами» |
| Модератор не получает уведомления в ЛС | он не нажимал `/start` у бота |
| ID убрали из `MODERATOR_IDS`, а человек всё ещё модератор | роли живут в БД — снимите через «Управление → Модераторы» |
| В меню «Управление» нет раздела «Модераторы» | аккаунт — модератор, а не администратор |
| Таблиц нет / ошибки SQL при старте | автомиграции выключены (`DB_AUTO_MIGRATE=false`) |
| FSM слетает после рестарта | не задан `REDIS_URL` |
